## The job

I own two things: the repository, and the definition of *correct*.

The repository means the layout, the build system, CI and the branch rules —
the things nobody else can start without — plus reviewing and merging every
pull request. The definition of correct means the golden model: an independent
Python reference for what each instruction must produce, so that "the RTL
works" is a test result rather than an opinion, and a disagreement points at
exactly one of two places instead of at a vague feeling that something is off.

On top of that I assemble the report: the IEEEtran template, the Abstract, the
References and the final PDF.

## What I built

1. **`golden/golden_model.py`** — a bit-exact Python reference for the six vector
   ops. Standard library only, 32 unit tests.
2. **`golden/gen_vectors.py`** — deterministic, seeded test-vector generation into
   `sim/vectors/`. Vector pair 0 is crafted rather than random, so the compares
   actually discriminate.
3. **`tb/tb_system.v`** — self-checking system testbench: runs `simd_top` on the
   benchmark, compares data memory against the golden vectors, prints one PASS
   or FAIL line.
4. **The repository and its scaffold** — directory layout, frozen port lists for
   all eight modules, `sim/Makefile`, CI, and this documentation set. Everyone
   else started from a tree where their module's ports already compiled, so
   nobody spent Saturday blocked on someone else's interface.
5. **Block diagrams** (`docs/diagrams/`) — top level, datapath and one lane,
   authored as SVG so each is a reviewable text diff, with PNG and PDF
   generated by `make -C docs/diagrams`.

## Why I built it that way

**The golden model is Python, not more Verilog.** A reference written in the same
language and the same mental model as the thing it checks tends to repeat the
same misreading of the spec. Python forced me to re-derive each op from
[`spec.md`](spec.md) independently.

**The one convention the model introduced is lane ordering.** Narrow compares
("1 or 0 in the lowest bit") and signed CMPLT both come from the team plan.
Lane order does not: the plan fixes `a[127:0]` and `y[127:0]` but never says
which end lane 0 sits at. The model puts lane 0 in the low 32 bits, matching the
natural `generate` index, and every committed vector follows it. Himanshu's
`vec_alu` has to agree — a reversal compiles cleanly and fails `tb_system` with
four wrong lanes and no obvious cause.

**The model uses no third-party libraries.** It defines what "correct" means for
this project. A numpy upgrade must not be able to change that.

**Vector pair 0 is crafted, not random.** Random 16-bit values made every lane
answer the compares identically — a test that passes with the comparator
deleted. The crafted pair covers equal, greater, less, and the signed case
(`-1 < 1`) that an unsigned comparator gets wrong, plus an ADD that wraps.

**The seed is fixed and the vectors are committed.** Everyone regenerates
byte-identical files, and CI fails if the committed expectations drift from the
model — otherwise correct RTL gets blamed for a stale expectation file.

**A stub reports SKIP, never PASS.** Every testbench counts its checks and prints
SKIP while that count is zero. A scaffold that printed PASS with nothing
asserted would let all five of us tick off work nobody had done.
